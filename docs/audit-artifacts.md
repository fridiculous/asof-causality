# Audit Artifacts

asof-causality emits machine-readable audit artifacts rather than only printing
`PASS` to stdout. The artifacts answer:

```text
which data, which signal, which executable context, which checks, and which
prediction transcript produced this result?
```

## Audit JSONL

`asof audit` emits one JSON object per replay-derived `PredictionRecord`.

Each record includes:

- `prediction_id`
- `prediction_replay_key`
- `signal`
- `symbol`
- `signal_value`
- `input_event_ids`
- `max_input_replay_key`
- `feature_recipe_hash`
- `causally_valid`
- optional `matched_stored_prediction`
- optional `outcome`

The schema is [schemas/audit.schema.json](../schemas/audit.schema.json).

## Feature Recipe Hash

`feature_recipe_hash` is a BLAKE3 commitment to:

```text
signal name + signal configuration descriptor + ordered input event keys
```

It is currently an input-set commitment, not an input-value commitment. It does
not separately commit to payload values or replay ordering metadata. Future
schema versions can commit to fuller feature recipes, input value snapshots, or
Merkleized recipe manifests without changing the core causality invariant.

## Stored Prediction Audits

Replay-only audit proves the signal stream generated by the kernel is causal.
Stored prediction audit compares replay-derived predictions against an external
prediction JSONL file.

Stored predictions are matched by:

```text
(symbol, prediction_replay_key)
```

They should include `signal_value` and `feature_recipe_hash`. The
`--allow-missing-recipe-hash` flag exists for legacy imports only; using it
weakens certification because the stored prediction is no longer bound to the
same input recipe as replay.

## Outcomes

Outcomes are attached after replay and are excluded from signal state. The audit
record can carry `return_bps`, but the engine does not score returns, compute
PnL, or certify strategy profitability.

The current CLI outcome adapter joins on `(symbol, prediction_replay_key)` for
strict fixture audits. Production outcome APIs should accept economic target
keys such as `(symbol, target_timestamp, horizon)` and resolve replay identity
inside the platform.

## Run Manifest

`run-suite` writes `manifest.json` beside:

```text
events.pipe
predictions.pipe
checks.txt
summary.md
```

The manifest records:

- schema version
- tool name and hash algorithm
- invocation and invocation args
- UTC run timestamp
- source commit, dirty flag, and Rust toolchain when available
- scenario and signal
- fixture, prediction output, checks output, and transcript hashes
- check pass/fail counts

The current run-suite manifest schema is version `4`; the version was bumped
when the executable tool identity changed to `asof`. The schema is
[schemas/manifest.schema.json](../schemas/manifest.schema.json).
The `transcript_hash` field is the same 64-character BLAKE3 transcript digest
printed by `replay`, `check`, `negative-control`, `sensitivity`, and
`run-suite`.

The manifest is a linkage proof for one run. It proves the artifacts belong
together; it does not prove that user-supplied `received_time` values were
authentic. Production deployments need the root-of-trust boundary described in
[architecture.md](architecture.md#the-root-of-trust).

## Sensitivity Artifacts

`asof sensitivity` writes:

- `summary.jsonl`
- optional `details.jsonl`
- `manifest.json`
- SVG charts such as `sensitivity-curve.svg`, `flip-rate.svg`,
  `input-change.svg`, and `late-arrival-impact.svg`

Schemas:

- [schemas/sensitivity.summary.schema.json](../schemas/sensitivity.summary.schema.json)
- [schemas/sensitivity.detail.schema.json](../schemas/sensitivity.detail.schema.json)
- [schemas/sensitivity.manifest.schema.json](../schemas/sensitivity.manifest.schema.json)

The current sensitivity manifest schema version is `sensitivity-v2`; it uses
`tool: "asof"` for the executable runner.

Sensitivity is a stability analysis outside the strict kernel. It asks how much
signal output changes under controlled timestamp perturbations; it does not
certify alpha.

## What A Green Audit Means

A green audit means:

```text
Every replay-derived prediction used only inputs available at its replay key.
```

It does not mean:

```text
The signal is predictive.
The strategy is profitable.
The input timestamps are authentic.
The fill model is realistic.
The universe construction is correct.
The portfolio simulation is valid.
```
